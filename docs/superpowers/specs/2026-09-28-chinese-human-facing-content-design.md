# 人类可读内容全面中文化设计

## 目标

将仓库中面向使用者和开发者阅读的内容统一为中文，同时保持代码接口、实验数据格式和已有命令兼容。

## 翻译范围

- `README.md` 与 `docs/**/*.md` 中的标题、正文、表格说明和操作指引；
- Python 源码中的注释与文档字符串；
- 命令行程序的命令说明、参数帮助和面向用户的输出；
- 异常消息、校验消息及其他需要用户理解的诊断文本；
- 测试中的说明性注释、文档字符串和显式断言消息。

## 保留内容

下列内容保持原样，避免破坏兼容性或降低技术表达的准确性：

- Python 标识符、模块路径、类名、函数名和类型名；
- 命令名、命令行参数、文件名与目录名；
- JSON/CSV 字段名、配置键、环境变量和机器可读枚举值；
- Git 提交示例、代码片段以及代码输出中的协议字段；
- Python、NumPy、scikit-learn、VTK、EGL、NVML、GPU、EFT、P50/P95/P99 等通用名称；
- Round Robin、Least Queue、Static Weighted、EWMA-EFT、Feature-EFT 和 Oracle-EFT 等正式策略名。

## 实施方式

逐文件翻译，不做与语言无关的重构。修改异常消息后，同步更新依赖消息匹配的测试。机器可读结果值继续使用既有英文枚举，以保证旧配置、轨迹和分析脚本仍可读取。

## 验收标准

1. 仓库内所有纳入范围的人类可读内容均为中文，必要的保留项除外；
2. 全文扫描剩余英文，并逐项判断其是否属于明确保留内容；
3. `ruff check src tests` 通过；
4. 全部测试通过；
5. CLI 总帮助及各子命令帮助能够正常显示中文；
6. Git 差异仅包含中文化及相应测试适配，不改变算法行为和数据格式。
